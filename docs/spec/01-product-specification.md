## 1. 產品概述

### 1.1 產品定位

Fin8d 是面向台灣中小企業的**雲端財務核心系統**，以 API-first、現代化 UI 為差異化，Phase 1 聚焦「可獨立運作的會計底層」，後續模組化擴展帳款、進銷、發票與合規功能。

### 1.2 目標用戶

| 角色 | 描述 | 核心需求 |
|------|------|----------|
| 中小企業會計 | 1–3 人財務團隊 | 傳票登打、月結、三大報表 |
| 財務主管 | 審核與關帳決策 | 審核流程、期間鎖定、報表 |
| 系統管理員 | IT 或代記帳設定 | 主檔、權限、公司參數 |
| 外部整合（Phase 2+） | 電商、POS、HR | REST API 串接 |

### 1.3 產品目標（Phase 1）

1. 可手動登打並審核會計傳票
2. 借貸自動平衡檢核
3. 產出試算表、資產負債表、損益表、科目餘額
4. 支援會計期間關帳與凍結
5. 完整主檔維護（科目、幣別、部門、往來對象等）

### 1.4 成功指標（KPI）

| 指標 | 目標 |
|------|------|
| 傳票登打至存檔 | ≤ 3 分鐘 / 張（5 行分錄） |
| 月結關帳操作 | ≤ 15 分鐘（含報表產出） |
| 報表產生時間 | ≤ 10 秒（12 個月資料） |
| 系統可用性 | 99.5%（dev 環境除外） |

## 2. 範圍定義

### 2.1 Phase 1 — In Scope

| 模組 | 功能 |
|------|------|
| **認證** | Email/密碼登入、Session、密碼重設 |
| **主檔** | 會計科目、幣別/匯率、銀行帳戶、部門、客戶/廠商 |
| **總帳** | 傳票 CRUD、借貸平衡、傳票類別、草稿/送審/核准/作廢 |
| **報表** | 試算表、資產負債表、損益表、科目餘額明細 |
| **系統** | 使用者與角色、公司參數、會計年度/期間、關帳 |

### 2.2 Phase 1 — Out of Scope

- 應收/應付帳款（Phase 2）
- 進銷存、電子發票（Phase 3）
- 固定資產、預算、電子簽核（Phase 4）
- 多公司/多帳套（Phase 1 僅單一公司）
- 行動 App（Phase 1 僅 Responsive Web）

### 2.3 假設與依賴

- 部署於 Zeabur（dev：`fin8d.intelligrate.com.tw`）
- PostgreSQL：`fin8d_dev` / `fin8d_user`
- 會計準則：台灣一般公認會計原則（GAAP）為預設
- 記帳幣別：TWD 為本位幣

## 4. 非功能需求

### 4.1 效能

- API P95 回應 < 500ms（不含報表）
- 報表查詢 P95 < 10s
- 支援同時 20 位使用者（Phase 1）

### 4.2 安全

- HTTPS 強制
- 密碼 bcrypt 雜湊
- RBAC 權限控管
- 操作稽核 log（傳票異動、關帳）
- SQL injection / XSS 防護

### 4.3 可用性

- 繁體中文 UI
- 鍵盤快捷（傳票登打 Tab 跳欄）
- 錯誤訊息可理解、可修正

### 4.4 相容性

- Chrome、Edge、Safari 最新兩版
- 1280px 以上桌面最佳；768px 以上可基本操作

## 5. 會計業務規則（Phase 1）

### 5.1 傳票規則

- 每張傳票借方合計 = 貸方合計
- 已關帳期間不可新增/修改傳票
- 已核准傳票不可直接修改，需沖銷或反過帳（Phase 1：僅允許作廢未過帳草稿）
- 傳票編號：自動流水，格式 `V{YYYYMM}-{SEQ:5}`

### 5.2 會計科目

- 支援 4 層樹狀結構
- 科目類型：資產、負債、權益、收入、費用
- 明細科目才可過帳；統制科目不可直接分錄

### 5.3 關帳

- 按月關帳；關帳後該月不可異動
- 關帳前檢查：試算表借貸平衡、無草稿傳票
